# DuckQuery 桌面版 · 新手使用手册（v1.1.5）

> 一句话介绍：DuckQuery 是一个跑在你自己电脑上的可视化数据查询工具。把 CSV / Excel 拖进来，就能用 SQL 或说人话分析数据。**数据默认全程在本机处理**；只有你主动使用 AI 功能时，才会把必要的上下文发给你自己配置的模型服务（详见 [FAQ](#9-常见问题-faq)）。
>
> 这份手册面向第一次使用的同学，不需要任何编程基础。

---

**本手册的四位主角**

他们和你一样，手边有一份数据文件，脑子里有一个想回答的问题：

| 主角 | 手里的文件 | 想回答的问题 | 直接跳到 |
|---|---|---|---|
| 运营小林 | `直播带货明细.csv`（从飞书导出，打开是乱码） | 上个月哪场直播的 GMV 最高？ | [第 4 节](#4-导入-csv) |
| 产品小周 | `用户反馈.xlsx`（6 个 sheet，按月分） | 半年的吐槽里，哪些问题最高频？ | [第 5 节](#5-导入-excel多个工作表) |
| 财务小陈 | `渠道对账表.xlsx`（表头有合并单元格） | 按渠道把金额汇总一下 | [第 5 节子节](#表头有合并单元格会出错吗) |
| 行政小吴 | 一张已导入的订单表 | 这个月北京区域退款超 500 的订单有哪些？（完全不懂 SQL） | [第 8 节](#8-不会写-sql用对话说人话) |

认出自己了就直接跳，从头读一遍也没有问题，大概 10 分钟。

## 1. 我该下哪个安装包？

前往下载页：**https://github.com/Chenkeliang/duckdb-query/releases**

下载页列出的文件里，你只需要下其中 **1 个安装包**——对照下表挑就行（`.sig`、`.app.tar.gz` 等其余文件是应用内自动更新用的，不用下载）：

| 你的电脑 | 下载这个文件 |
|---|---|
| **Windows 10 / 11（64 位）** | `DuckQuery_1.1.5_x64-setup.exe` |
| **Mac，Apple 芯片（M1 / M2 / M3 / M4）** | `DuckQuery_1.1.5_aarch64.dmg` |
| **Mac，Intel 处理器** | `DuckQuery_1.1.5_x64.dmg` |

> 文件名里的 `1.1.5` 是版本号，以下载页当时的最新版本为准。

**不确定 Mac 是哪款芯片？** 点屏幕左上角苹果图标 → 「关于本机」，看「芯片」或「处理器」那一行：
- 写着 **Apple M1 / M2 / M3 / M4** → 下 `aarch64.dmg`
- 写着 **Intel** → 下 `x64.dmg`

系统要求：**macOS 13 (Ventura) 及以上** / **Windows 10、11（64 位）**。

## 2. 安装时弹出警告怎么办？

### Windows：蓝色窗口「Windows 已保护你的电脑」

双击 `.exe` 文件后，可能弹出蓝色窗口，写着「**Windows 已保护你的电脑 / Windows protected your PC**」。这是 Windows 对没有商业签名证书的程序的默认拦截，与病毒无关，是正常现象。只需两步绕过：

1. 点蓝色窗口里的 **「更多信息 / More info」**（蓝色链接文字）
2. 窗口下方出现 **「仍要运行 / Run anyway」**，点它

之后按提示一路安装。默认只安装到当前用户，**不需要管理员权限**。安装包自带浏览器内核（WebView2），**全程不需要联网**。

✅ **成功的样子：** 安装程序窗口关闭，桌面或开始菜单出现 DuckQuery 图标。

---

### macOS：提示「已损坏，无法打开」或「无法验证开发者」

这不是真的损坏——macOS 对没有苹果开发者签名的软件默认这样拦截。用终端一条命令就能解除，只需做一次，以后直接双击。

**Step 1：把 App 放进「应用程序」**

双击下载好的 `.dmg` 文件，把里面的 **DuckQuery 图标拖到旁边的「应用程序 / Applications」文件夹**，拖完关掉这个窗口。

**Step 2：在终端解除拦截**（只需做一次）

打开「终端」最快的方式：同时按键盘上的 **Command（⌘）+ 空格**，出现搜索框后输入「终端」，双击出现的「终端」应用即可打开。

也可以通过文件夹找：「访达 / Finder」→「应用程序 / Applications」→「实用工具 / Utilities」→ 双击「**终端 / Terminal**」。

把下面这一行**完整复制**粘贴进终端，按回车：

```bash
xattr -cr /Applications/DuckQuery.app
```

**命令执行后会看到什么：**

- **回车后没有任何文字出现，光标直接另起一行** — 这就是成功了。关掉终端即可，不需要等任何确认提示。
- **报错「No such file or directory」** — 说明 App 没放在「应用程序」文件夹里，回 Step 1 重新拖一次。
- **报错「Operation not permitted」** — 极少数情况，在命令前面加 `sudo ` 再执行（即 `sudo xattr -cr /Applications/DuckQuery.app`），这时才会要求输入开机密码，输入时屏幕不回显是正常的，打完直接按回车。

**Step 3：正常打开**

关掉终端，回到「应用程序」文件夹，双击 DuckQuery，这次能正常打开。以后每次也是直接双击，不需要再做上面的操作。

> 如果提示的是「无法验证开发者」（不是「已损坏」），也可以尝试：在「应用程序」里**右键 DuckQuery → 「打开」→ 弹窗里再点「打开」**。但若提示的是「已损坏」，这条路走不通，必须用上面的终端命令。

## 3. 第一次打开，界面长什么样？

首次启动会有欢迎页，点 **「开始使用」** 进入主界面。

欢迎页关闭后，你进入正式界面：左侧是竖排的图标按钮，中间是一片空白的操作区——此时软件里还没有任何数据，这是正常的。

如果出现「**正在启动本地引擎…**」，等它消失再操作，通常不超过几秒（首次启动可能要 1-2 分钟）。v1.1.4 起，万一启动失败，页面会直接显示失败原因、建议排查和「打开日志位置」按钮，按提示处理即可——详见 [FAQ](#9-常见问题-faq)。

**接下来你要做的第一件事：去左侧点「数据源」，把文件导进来。**

左侧固定有 **5 个导航按钮**，整个软件的操作都从这里进：

| 左侧按钮 | 你在什么时候点它 |
|---|---|
| **数据源** | 要把文件导进来时，第一步来这里 |
| **查询工作台** | 文件导进来后，在这里写 SQL 或用「对话」提问、看结果 |
| **AI 模型** | 用「对话」前，来这里配一次 AI 供应商（只配一次） |
| **扩展** | 管理 DuckDB 扩展；一般用不到，保持默认即可 |
| **设置** | 改界面语言、主题、查询行数上限时来这里，平时用不到 |

这 5 个按钮在窗口左侧的竖栏里，每个按钮是一个图标加一行文字。侧边栏可以折叠，折叠后中间操作区更宽——点侧边栏顶部 Logo 右侧的折叠按钮即可收起；折叠后左侧只剩图标，点左侧底部的展开按钮可以再展开。

## 4. 导入 CSV

📌 **场景：运营小林**

小林从飞书下载了「直播带货明细.csv」，想看上个月哪场直播的 GMV 最高。要查数据，第一步是先把文件导进 DuckQuery。

**入口**

点左侧 **「数据源」** → 顶部切到 **「文件上传」** 标签 → 上方分段选择器保持默认 **「智能文件上传」** 不用动。

页面中间出现一个虚线边框区域，写着「拖放文件到此处」，支持格式：`.csv .xlsx .xls .json .jsonl .parquet`。

两种放入方式，选一种：
- 直接把文件**拖进虚线框**
- **点一下虚线框**，在弹出的系统文件窗口里选文件

**选好文件后，一般情况不需要动任何选项，直接点底部「开始上传」**。按钮变为「上传中 X%」，大文件会自动分块上传，等进度跑完即可。

✅ **成功的样子：** 出现提示「**文件上传成功，已创建表: 直播带货明细**」。这张表就出现在「查询工作台」左侧列表里，随时可以查询了。

接下来去「查询工作台」写 SQL 或说人话——见[第 6 节](#6-查询数据会写-sql-的同学)（会写 SQL）或[第 8 节](#8-不会写-sql用对话说人话)（不会写 SQL）。

---

**遇到问题再展开「CSV 高级选项」**

选中 `.csv` 文件后，下方会出现「CSV 高级选项」（可展开）。大多数情况不需要改，遇到下面这两个典型问题时调：

**中文全是乱码（方块或问号）？**

展开「CSV 高级选项」，把「**编码**」改成 **`GB18030 (GBK/GB2312)`**，重新点「开始上传」。国内大多数系统导出的 CSV 用的是这个编码，改了就正常了。

**订单号、手机号变成了 `1.38E12` 这样的科学计数法？**

**无需展开「CSV 高级选项」**。页面上方有一个「**数据类型**」下拉框，默认显示「自动识别（推荐）」，把它改成「**全部按文本**」，再点「开始上传」即可。

「CSV 高级选项」里其他字段说明：

| 选项 | 默认 | 什么时候改 |
|---|---|---|
| **分隔符** | 自动检测 | 识别出错时，手动填入正确分隔符（如 `;` 或制表符） |
| **表头** | 自动 | 第一行不是列名时，改「无表头」 |
| **编码** | 自动检测 | 中文乱码时改 `GB18030 (GBK/GB2312)` |

另外，虚线框下方有一个「**表别名（可选）**」输入框，可以给这张表起一个不同的名字，留空则使用文件名。

## 5. 导入 Excel（多个工作表）

📌 **场景：产品小周 / 财务小陈**

小周的「用户反馈.xlsx」有 6 个 sheet，小陈的「渠道对账表.xlsx」表头有合并单元格。他们的文件不是普通的单表 CSV，但导入入口是一样的——上传完成后，软件会弹出一个专门的对话框让你配置 sheet。

**入口与 CSV 相同**

左侧「数据源」→「文件上传」→ 拖入或选择 `.xlsx` 文件 → 点「开始上传」。

**文件上传完成后，软件自动弹出对话框「Excel 工作表导入」**（副标题：选择要导入的工作表并确认表头设置）——这是因为一个 Excel 可能有很多 sheet，软件需要你说清楚要导哪几个。

**操作步骤**

1. 小周想把 6 个月全导进来：点顶部 **「全选」**，所有 sheet 全部打勾。每个 sheet 旁边显示「X 行 × X 列」，可以对照原文件核对数量是否对得上。

2. 点开某个 sheet 展开详情，确认：
   - **目标表名**：这个 sheet 在软件里叫什么，默认用 sheet 名
   - **表头行数**：通常填 `1`（第一行是列名）
   - **表头起始行号**：表头从哪行开始，一般不用动
   - **数据预览**：下方显示前 5 行，核对列名和内容识别是否正确

3. 确认无误，点 **「导入选中的工作表」**。

✅ **成功的样子：** 对话框关闭，左侧「查询工作台」→「DuckDB 表」列表里出现所有导入的 sheet，每个 sheet 对应一张独立的表。

接下来去「查询工作台」查——产品小周可以用[第 8 节](#8-不会写-sql用对话说人话)的「对话」功能把 6 张表合并提问高频词。

🙋 **导入后左侧没出现新表？** 检查弹窗里有没有勾选 sheet——空框不会被导入，确认勾选框是打勾状态。

### 表头有合并单元格，会出错吗？

📌 **场景：财务小陈**

小陈的渠道对账表，「天猫」「京东」「抖音」三个渠道名各自横跨了几列做成了合并单元格。直接导入的话，被合并的列里只有第一格有值，其余格为空——之后按渠道 GROUP BY 就会漏数据。

**DuckQuery 有专门的开关处理这个问题。**

在「Excel 工作表导入」对话框里，展开有合并单元格的工作表，软件检测到合并单元格后会提醒你，并显示 **「填充合并单元格」** 开关——**建议把它打开**。

打开后，合并区域的值会向下填充到每一格：原来「天猫」下面 3 列只有第一列有「天猫」，开关打开后 3 列都会有「天猫」，按渠道汇总才不会漏。

查看「数据预览」，对照原始 Excel 确认前 5 行列名和内容与预期一致，然后点 **「导入选中的工作表」**。

✅ **成功的样子：** 导入后在「查询工作台」右键表名 → 「预览数据」，原来合并的列现在每行都有值，没有空白，可以正常 GROUP BY 了。

## 6. 查询数据（会写 SQL 的同学）

📌 **场景延续：运营小林**

「直播带货明细」已经导进来了。点左侧 **「查询工作台」**，左侧「DuckDB 表」下出现了「直播带货明细」这一行——这就是刚才导进来的表。

双击表名，中间编辑区自动填入 `SELECT * FROM 直播带货明细 LIMIT 100`，按 **Ctrl+Enter** 先预览一下全貌。

把查询改成你真正想问的：

```sql
SELECT 直播名称, SUM(GMV) as 总GMV
FROM 直播带货明细
GROUP BY 直播名称
ORDER BY 总GMV DESC
```

按 **Ctrl+Enter**（Mac 也是 Ctrl+Enter）执行。

✅ **成功的样子：** 下方结果区出现一张按 GMV 倒序排列的表格，每行是一场直播和对应的 GMV 汇总。

---

**左侧数据源面板**

左侧「数据源面板」分两组：
- **「DuckDB 表」** — 你导进来的本地文件表在这里
- **「数据库连接」** — 连接的外部 MySQL / PostgreSQL 在这里

顶部有一个搜索框（placeholder「搜索表...」），表多时可以用它快速定位。

**表名操作：**

| 操作 | 效果 |
|---|---|
| 单击表名 | 选中 |
| 双击表名 | 把表名插入 SQL 编辑器当前光标位置 |
| 右键表名 | 弹出菜单：「预览数据」/「查看结构」/「数据画像」/「导出数据」/「删除表」 |

**中间 4 个查询 Tab，按需选用：**

| Tab | 适合什么情况 |
|---|---|
| **SQL 查询** | 直接写 SQL；`Ctrl+Space` 打开补全，`Ctrl+Enter` 执行 |
| **JOIN 查询** | 想关联两张表但不想手写 JOIN——例如小林还有一张「主播信息表」，想按主播 ID 关联 |
| **集合操作** | 做 UNION / 取交集 / 取差集 |
| **透视表** | 想直接拖字段做交叉汇总，不想写 GROUP BY |

## 7. 配置 AI（用「对话」前的一次性设置）

你点了「对话」之后，按钮旁出现「需先配置 AI 供应商」——那就点左侧「AI 模型」来做这一次性设置。配完之后「对话」就能用了，以后不需要再回来。

点左侧 **「AI 模型」**，你会看到卡片「**AI / 模型**」，右上角有 **「启用 AI」** 开关，默认是关闭的——先把它打开。

### 配置供应商：OpenAI / Anthropic / 本地 Ollama / OpenAI 兼容

点页面底部的 **「新增供应商」** 按钮，页面出现一行新的供应商卡片并自动展开，依次填写：

| 字段 | 说明 |
|---|---|
| **供应商名称** | 随便起，如 `我的GPT` |
| **类型** | 选 `OpenAI` / `Anthropic` / `Ollama (本地)` / `OpenAI 兼容` |
| **模型（逗号分隔）** | 填你要用的模型名，多个用英文逗号隔开 |
| **接口地址** | 仅 `Ollama (本地)` 和 `OpenAI 兼容` 需要填，如 `http://localhost:11434` |
| **API Key** | 填你的密钥（密码框；已填过则显示掩码 `已配置 ****`，留空则保持不变；密钥只存在本机服务端，不上传） |

> ⚠️ `OpenAI 兼容` 类型的接口地址只填到 `/v1` 为止。系统会自动追加 `/chat/completions`，不要自己加后缀，也不要出现多余的 `//`。

填好后，点该供应商行右侧 **「测试」** 按钮确认连通，再点页面底部 **「保存」**，出现提示「**AI 设置已保存**」就完成了。

## 8. 不会写 SQL，用「对话」说人话

📌 **场景：行政小吴**

小吴手里有一张订单明细表，已经导入了 DuckQuery。她想知道「这个月北京区域退款金额超过 500 的订单有哪些」，但完全不懂 SQL。

**前提：先完成[第 7 节](#7-配置-ai用对话前的一次性设置)配好 AI**（只需配一次，配完就能一直用）。

**配完后，回到「查询工作台」**

点左侧「查询工作台」，进入「SQL 查询」Tab，找到工具栏右侧的 **「对话」** 按钮（消息气泡图标），点击后屏幕右侧滑出「数据助手」抽屉。

**在「对话」抽屉里说人话：**

在抽屉底部输入框（placeholder「问数据助手…（Enter 发送）」）里输入你的问题，例如：

「这个月北京区域的订单里退款金额超过 500 的有哪些」

按 **Enter** 发送。

**你会看到：** AI 在抽屉里回复，回复中包含一段 SQL 代码，代码块下方有 **「插入编辑器」** 按钮——点它，SQL 才填入中间编辑区。

SQL 填进来后还没有跑。你先看一眼逻辑是否符合意图，然后按 **Ctrl+Enter**，结果才会出来。

🙋 **最常见的误解：** 发送问题后很多人等着结果出来，但结果不会自动出现。AI 只是把 SQL 写好放进了抽屉，**你还需要点「插入编辑器」，再自己按 Ctrl+Enter 执行**。这是故意设计成这样的——让你有机会审核一下再决定要不要跑。

> 对话抽屉里专门提示「生成的 SQL 可一键插入编辑器，绝不自动执行」——AI 永远不会替你跑数据，每次都需要你主动确认才执行。

## 9. 常见问题 FAQ

**Q：Mac 提示「已损坏，无法打开」怎么办？**

不是真损坏，是 macOS 对未签名软件的默认拦截。打开「终端」（最快方式：Command+空格 搜索「终端」），粘贴并回车：`xattr -cr /Applications/DuckQuery.app`。命令执行后不会有任何提示文字，光标另起一行就是成功了，关掉终端正常双击即可。以后不需要再做这个操作。详见 [第 2 节 macOS 拦截](#macos提示已损坏无法打开或无法验证开发者)。

---

**Q：Windows 弹出「Windows 已保护你的电脑」怎么处理？**

点「更多信息 / More info」→「仍要运行 / Run anyway」。软件没有购买商业签名证书，Windows 对所有未签名程序都会这样拦截，正常现象，不是病毒。

---

**Q：首次启动一直卡在「正在启动本地引擎…」？**

首次启动要初始化本地引擎，**可能需要 1-2 分钟，请耐心等待**（之后每次启动都很快）。v1.1.4 根治了几类启动超时问题，并把失败页做成了可自助诊断——真的失败时，页面会直接显示失败原因和「建议排查」，请确认你用的是 1.1.4 及以上版本。如果仍然卡住或失败：

1. **完全退出软件后重新打开一次**——大多数情况第二次就能正常进入（第一次慢通常是杀毒软件在逐个扫描新程序的文件，扫完就放行了）。
2. **公司电脑装有企业杀毒软件的**：请 IT 或自行把 DuckQuery 的安装目录加入杀毒软件的信任/排除列表，首次启动会明显变快。
3. 仍不行：点失败页的 **「打开日志位置」** 按钮（或手动进入数据目录：Windows `C:\Users\你的用户名\AppData\Roaming\DuckQuery\`；Mac `~/Library/Application Support/DuckQuery/`），把 `engine-stderr.log` 和 `startup.log` 两个文件发给开发者即可快速定位卡在哪一步。

---

**Q：怎么升级到新版本？**

不需要重新下载安装包。软件启动时会自动向 GitHub Releases 检查新版本，有更新会提示，确认后自动下载安装并重启；更新包经过签名校验，来源可信。

---

**Q：CSV 导进来中文全是乱码/方块怎么办？**

上传时展开「CSV 高级选项」，把「编码」改成 **`GB18030 (GBK/GB2312)`**，重新上传。

---

**Q：订单号、手机号变成了 `1.38E12` 这样的数字？**

上传时，在页面上方找到「**数据类型**」下拉框（不在「CSV 高级选项」里），把它改成「**全部按文本**」，重新上传。

---

**Q：发了问题之后没有 SQL 结果出来？**

AI 在右侧「对话」抽屉里回复，回复里的 SQL 需要你点 **「插入编辑器」** 才会进入编辑区，然后再按 **Ctrl+Enter** 执行，结果才会出来。

---

**Q：AI「测试」按钮报错，怎么排查？**

最常见的原因是接口地址填多了后缀。检查「接口地址」一栏，确保只填到 `/v1` 结尾，没有 `/chat/completions` 也没有多余的 `//`。再确认 API Key 没有多余的空格。

---

**Q：导入的表不见了，或者想删掉某张表？**

去「查询工作台」，左侧「DuckDB 表」列表里找到该表，**右键 → 「删除表」**。

---

**Q：数据会上传到云端吗？**

不会。CSV / Excel 的导入和查询全部在你本机完成，数据不离开你的电脑。只有当你主动使用 AI 功能（对话、报错医生、图表建议等）时，才会按具体功能把你输入的**问题文字、表结构、SQL、报错上下文或少量结果样例**发给**你自己配置的** AI 供应商。不使用 AI 时，软件唯一的外部访问是启动时向 GitHub 检查新版本（不包含任何你的数据）。

---
