# DuckQuery v2.1.3 Release Notes

This hotfix repairs Windows overlay upgrades where a renamed DuckDB native module prevented the local engine from starting. It also provides MCP 0.4.1.

## Windows upgrade repair

- v2.1.1 shipped an ABI-tagged DuckDB module; v2.1.2 switched to an untagged filename. Auto-update overlays files without first uninstalling the old directory, leaving the older, higher-priority module in place and causing `cannot import name 'Appender' from '_duckdb'`.
- Windows bundles now consistently use the ABI-tagged filename preferred by the active Python interpreter, so an update overwrites that module. Builds reject missing or ambiguous native modules.
- There is no startup file deletion or blanket cleanup of installation/user directories. Existing databases, saved connections and keys retain their locations and require no re-import.
- Upgrade directly from v2.1.1 or overlay this installer on an installation broken by v2.1.2. Fully exit the app before running the repair installer, and keep database/WAL backups before upgrading.

## MCP 0.4.1

- Query results retain optional backend column types, actual pushdown diagnostics and warnings. Existing columns, rows, row_count, truncated and row caps are unchanged.
- Three new read-only tools suggest type-based metrics, discover filtered JSON paths and generate exploration SQL. Generation does not execute SQL; use the existing query tools afterward.
- Corrected pivot documentation: legacy execute=True calls SQL generation only and does not execute or create a table. Its existing confirmation requirement and exposure rules remain unchanged; old calls do not become writes.
- read-only, normal and full safety modes retain their existing write-confirmation gates, generic POST restrictions and backend safeguards.
- New exploration tools require DuckQuery >=2.1.2. Existing tools remain compatible with older backends. Desktop and MCP package versions are independent; the Windows startup repair does not require an MCP upgrade.

## Versions and validation

App: 2.1.3. DuckDB Python/engine: unchanged at 2.0.0 / v2.0.0. MCP: 0.4.1. The v2.1.2 data exploration, safe MySQL candidate filtering and compact extension UI are retained. The new-database storage format remains v2.0.0; there is no additional migration.

A native Windows installer regression uses the published v2.1.1/v2.1.2 installers to exercise direct upgrades and repair of broken installations. The baseline must reproduce the Appender import error; the candidate must restore the selected native module and backend health while preserving tables, connections, keys and configuration. CI uses disposable users and synthetic data, without business database access. All platforms retain frozen-backend smoke tests, and publication waits for all build/upgrade checks.

The MCP wheel and source distribution accompany this GitHub Release. PyPI availability depends on its actual publication state; see the [MCP documentation](https://github.com/Chenkeliang/duckdb-query/blob/v2.1.3/mcp/README.md) for installation options.
