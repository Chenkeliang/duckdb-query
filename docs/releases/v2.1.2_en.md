# DuckQuery v2.1.2 Release Notes

This release upgrades to stable DuckDB 2.0, adds schema-driven data exploration, and improves safe MySQL candidate filtering for statistics and joins. Extension management now uses compact rows and includes an official Avro installation entry.

## Data exploration and JSON extraction

- Select a table to configure operations suggested by actual column types: counts, distinct counts, sums, averages and temporal bounds. Suggestions do not infer business meaning. Review SQL before execution and display single-row results as metric cards.
- JSON discovery applies the current filters before sampling at most 100 rows. Changing a filter or source column clears the previous sample and extraction configuration; discover paths again. Sampled paths are not a complete schema.
- Extract selected JSON paths into separate columns. Text output preserves large integers by default; missing paths and failed casts return NULL. DOUBLE remains approximate floating point.
- Metrics cover all filtered input. Sampling and result-preview limits never truncate aggregate inputs.

## MySQL pushdown and result consistency

- Safely translated temporal, integer, DECIMAL and string predicates reduce candidates in MySQL; DuckDB retains the original exact filters and final joins.
- Equivalent single-table COUNT queries run at the source and return only counts. String distinct counts preserve case, accents and trailing spaces. SUM/AVG remain in DuckDB, and DECIMAL values are restored from text without rounding.
- Numeric and matching DECIMAL join keys support candidate reduction, including column projections produced by the JOIN designer. Large key sets use range envelopes followed by exact local joins, preserving duplicates, NULLs and outer-join preserved rows.
- The UI distinguishes planned and actual strategies and provides cancellation in data exploration. Unsupported expressions remain local. Native remote_pushdown is not globally enabled, and not every large-table query is guaranteed to become faster.
- Crosschecks fixed NOT LIKE and double negation, duplicate result names, transformed star projections, infinite date bounds, year-zero dates, incomplete month/day values and invalid calendar dates.

## Extensions

- Compact rows align extension names, purposes, states and actions. Expand SQL examples only when needed and copy them as before.
- Search by name or purpose and filter installed or available extensions. Empty results and loading failures have recovery actions; installation progress and retry retain the existing APIs.
- Avro is newly included in the curated catalog. Install the official extension and query files with `read_avro(...)`. Avro itself predates this release; the file-import picker has not gained Avro support.

## Engine and upgrade notes

- **App version: 2.1.2. DuckDB Python package: 2.0.0. Engine: stable v2.0.0.** App v2.1.1 used 1.6.0.dev379 / v2.0.0-alpha39998. The MCP package stays at 0.4.0. The browser Wasm demo uses a separate engine and does not include data exploration.
- The new-database storage format remains v2.0.0. Existing files are not automatically migrated at startup; upgrading from 2.1.x requires no additional storage migration. Back up main.db, system.db and their WAL files before upgrading.
- Extensions must match the stable engine and platform. Standard installers contain Excel; offline installers also include httpfs, MySQL and PostgreSQL. Avro requires an initial online installation and can then be used offline.
- Shutdown stops and joins the cancellation monitor before closing databases, fixing the known exit-reference warning. macOS Apple Silicon, macOS Intel and Windows x64 retain standard installers, offline installers and in-app updates.
- For upgrades from 1.x or rollback, read the [2.0 major-version notes](https://github.com/Chenkeliang/duckdb-query/blob/v2.0.0/docs/releases/v2.0.0_en.md) first.

## Validation scope

Regressions cover real DuckDB execution, the MySQL/PostgreSQL semantic matrix, three MySQL collations, numeric precision, date boundaries, duplicates, NULLs, outer joins, sampling and LIMIT. Extension-page checks cover search, state filters, expandable/copyable examples, progress and retry, with wide and narrow Web verification. The release workflow runs tests and quality checks before building all three platforms and executing frozen-backend smoke tests. The release is published only after all artifacts are complete.
