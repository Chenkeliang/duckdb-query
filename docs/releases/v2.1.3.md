# DuckQuery v2.1.3 发布说明

本次热修复解决 Windows 从旧版覆盖升级后，本地引擎因 DuckDB 二进制文件名变化而启动失败的问题，并同步提供 MCP 0.4.1。

## Windows 升级修复

- v2.1.1 的 DuckDB 模块带 Python ABI 标签，v2.1.2 改用了不带标签的文件名。自动更新覆盖文件但不会先卸载旧目录，导致旧文件残留并被 Python 优先加载，出现 `cannot import name 'Appender' from '_duckdb'`。
- v2.1.3 将 Windows 包中的 `_duckdb` 统一放到当前 Python 优先加载的 ABI 文件名，覆盖升级直接替换该文件；同时在构建时拒绝缺失或多份原生模块的异常包。
- 不增加启动时删文件、不清空安装目录或用户目录。已有数据库、连接配置和密钥沿用原路径，无需重新导入。
- 从 v2.1.1 可直接升级；已经因 v2.1.2 遇到上述崩溃的安装也可通过本包覆盖修复。修复前请完全退出应用再运行安装器，升级前保留数据库及 WAL 备份。

## MCP 0.4.1

- 查询结果保留后端提供的字段类型、实际下推信息和警告；原有 `columns`、`rows`、`row_count`、`truncated` 字段及行数上限保持不变。
- 新增三个专用只读工具：按类型推荐指标、按筛选采样发现 JSON 路径、生成统计/提取 SQL。生成工具不会自动执行 SQL；调用后仍需通过原查询工具执行。
- 修正透视工具说明：旧参数 `execute=True` 实际仅调用 SQL 生成接口，不会执行或写表；保留该参数原有确认要求和工具暴露规则，不把旧调用改成写入。
- `read-only`、`normal`、`full` 权限模式不变；原有写操作确认门控、泛化 POST 请求门控和后端限制继续生效。
- 新探索工具要求后端至少为 v2.1.2；原有工具继续支持旧后端。桌面版本和 MCP 包独立编号，旧 MCP 无需为了启动修复而强制升级。

## 版本与验证

应用版本为 2.1.3，DuckDB Python/引擎仍为 2.0.0 / v2.0.0，MCP 包为 0.4.1。保留 v2.1.2 的数据探索、MySQL 安全候选下推和紧凑扩展页；不新增存储迁移。

新增 Windows 原生安装器回归：使用已发布的 v2.1.1 和 v2.1.2 安装包，验证直接升级以及故障安装修复；故障基线必须先复现 Appender 导入错误，修复后必须验证实际加载的模块、后端健康、既有表、连接、密钥和配置均保留。CI 使用一次性用户和合成数据，不访问真实业务库。各平台继续执行冻结后端冒烟，所有构建和升级检查通过后才公开发布。

MCP wheel 与源码包随本次 GitHub Release 提供；PyPI 的可用版本以该索引实际发布结果为准，安装方式见 [MCP 文档](https://github.com/Chenkeliang/duckdb-query/blob/v2.1.3/mcp/README.md)。
