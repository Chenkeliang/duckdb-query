# DuckQuery v2.2.0 Release Notes

This release adds remote read-only Quack SQL, field expansion across data sources, and updated chart/AI recommendation interactions. Existing MySQL / PostgreSQL / SQLite / DuckDB connections and query builders remain available.

## Remote Quack Services

- A separate **Quack services** group in data-source management and the workbench accepts an existing service address and token. Browse its actual catalogs, schemas, tables, views, and column types. CSV / Parquet / DuckDB data is configured and exposed by the server; the client does not upload local files or manage the server's database connections.
- Each SQL tab binds to one service and executes on remote DuckDB. The client verifies a single read-only statement and rejects writes and dynamic-SQL wrappers. The service still needs its own authentication and database-level read-only permissions.
- Queued saves record the accepted service configuration revision. A change before connection causes an explicit failure rather than retargeting the task; an explicit retry captures the current configuration. Read-only checks cover quoted, qualified, and EXPLAIN-wrapped `checkpoint`, `force_checkpoint`, and `write_log` calls while preserving legal same-named aliases.
- Query cancellation, moving active queries to the background, result refresh, charts, export, and saving to local DuckDB are supported. Cancellation targets the query's remote connection ID; background adoption continues the same execution. Result actions retain the captured service when editors change.
- Local saves use a temporary native DuckDB file, preserving DECIMAL, large integers, nested types, and UNION member tags. Parquet exports use text columns for types that cannot be represented losslessly; UNION and nested UNION exports are explicitly rejected. Use CSV or local saves instead. See the [Quack guide (Chinese)](../guide/quack-services.md) for type details.
- Available in desktop and Python-backed Web/Docker deployments, not the browser-only Wasm demo. Visual JOIN, set operations, pivot, exploration, AI questions/repair for remote SQL, and SQL bookmarks are not integrated. Cross-service joins, remote writes, and hosting Quack servers are not provided.
- An explicit connection test installs official `httpfs` / `quack` extensions as needed. Current offline bundles do not include `quack`; restricted networks need matching official engine/platform extensions installed in advance. Connections originate from the backend machine; `localhost` inside Docker refers to its container.

## Data-Source Tree and SQL Preview

- Local DuckDB, existing database connections, and Quack tables support arrow-based field/type expansion with lazy metadata loading. Local/external expansion uses a separate structure-only request without full-table counts or content samples.
- Tree labels share font sizes and hierarchy. Double-click or choose **Open preview SQL (100 rows)** from the application context menu to fill SQL without executing it. Existing source-specific preview, import, structure, export, and deletion actions are preserved.
- Reopening identical SQL for the same Quack service refocuses its existing tab. Edited drafts and different services stay separate; explicit new queries still open independent tabs.
- Field caches distinguish table, connection, and schema, refresh after connection changes, and do not replace the rich metadata cache used by existing builders.

## Charts and AI Suggestions

- Existing chart/UI components are retained, with less-used configuration collapsed. Recommendations use field types and the current result. Charts default to plotting current SQL rows without silently aggregating them again or rerunning truncated queries.
- Grouping requires an explicit calculation, scope, and preview. Temporal plots sort dates and report duplicate/invalid dates and point limits. Default measures avoid identifier fields. Plot coordinates are approximate; tooltip text preserves original backend scalar precision.
- Current-scope recalculation retains the actual preview row cap. Removing the system preview cap requires an explicit choice; original user LIMIT/FETCH clauses and nested limits remain intact. Trailing line comments no longer break aggregation or drill-down SQL.
- AI suggestions run only after a click, sending current SQL, columns, a distribution summary of the current result, and at most five bounded sample rows to the configured model. Review chart type, fields, calculation, and reason before previewing. Stale suggestions do not replace newer results.

## Versions, Upgrades, and Validation

App version: **2.2.0**. DuckDB Python/engine remains **2.0.0 / v2.0.0**, and MCP remains **0.4.1**. No new MCP package is published and existing MCP tools/permission modes are unchanged. Dedicated Quack tools are not added to the Agent/MCP catalog.

New-database storage remains pinned to `v2.0.0`; no new storage migration is introduced. Databases, connections, and keys retain their locations. Back up data and WAL files before upgrading. The v2.1.3 Windows overlay-upgrade repair is retained. Standard builds serve in-app updates; offline installers are separate download assets.

Coverage includes read-only guards, same-named service isolation, cancellation/background adoption, numeric/native-type preservation, field caches, interactions, and charts. The release pipeline runs frontend/backend/MCP/Rust checks, frozen-backend smoke tests, all three platform builds, and Windows upgrades from published older versions, including broken-install recovery. Installers are made public only after all gates pass.
