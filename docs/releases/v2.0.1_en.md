# DuckQuery v2.0.1 Release Notes

This patch improves federated-query correctness, performance, and desktop workflows. MySQL queries, persistence, async execution, exports, and AI queries now share the same execution logic.

## Highlights

- **Faster MySQL reads with exact DuckDB results.** Eligible string equality and `IN` predicates narrow remote candidates; DuckDB retains exact filtering, JOINs, ordering, and LIMIT. This avoids collation differences affecting case, trailing spaces, or join multiplicity. Unsupported cases keep local evaluation.
- **Desktop SQL fixes.** `IN (..., NULL::VARCHAR)` no longer disables candidate filtering. Standalone `mysql_query('connection_alias', ...)` automatically attaches saved connections. Multiple aliases for one connection remain bound, and dollar-quoted remote SQL is not mistaken for local table references.
- **Precision preservation.** Decimal amounts, large integers, nanosecond timestamps, and JSON/VARIANT numeric text retain fidelity through querying, viewing, copying, persistence, and export. This also fixes some MySQL text results being exposed as BLOB and misplaced JSON-viewer translations.
- **Reliable persistence and cancellation.** Shared transaction and cleanup boundaries materialize saved results once. Cancellation survives registration races, failed or timed-out saves preserve existing result tables, and local saves no longer inherit federation-only timeouts.
- **Controlled PostgreSQL execution.** Remote deadlines follow the remaining query budget, cancellation targets the current task, and MySQL/PostgreSQL query attachments are read-only.
- **Clearer SQL diagnostics.** Structured Parser/Binder locations refer to the original SQL; stale errors do not mark edited content. Capability metadata reflects the current engine, extensions, and enabled optimizer policy.

## Upgrade notes

- Upgrading from **v2.0.0** requires no new storage migration. The application becomes **2.0.1**; DuckDB Python remains `1.6.0.dev379`, the engine remains `v2.0.0-alpha39998`, and new-database storage remains `v2.0.0`.
- DuckDB remains Preview. Users upgrading from 1.x should first read the [2.0 major-version upgrade notes](https://github.com/Chenkeliang/duckdb-query/blob/v2.0.0/docs/releases/v2.0.0_en.md) and back up their databases.
- Installers cover macOS Apple Silicon, macOS Intel, and Windows x64. Standard builds support in-app updates; `offline` builds suit environments without extension downloads.
- MCP stays at `0.4.0`; no separate MCP package upgrade is required for this patch.

## Validation

- Full backend suite: **1534 passed, 5 skipped**, including isolated MySQL 8.4 coverage. Additional MySQL 5.6 regression run: **167 passed**.
- Full frontend suite: **1280 passed, 1 skipped**. ESLint, TypeScript, production build, and backend pylint **10.00/10** passed.
- Direct UI testing in the rebuilt macOS application covered typed NULL, standalone `mysql_query`, multiple aliases, persistence, async execution, and Parquet export. Reading exported files confirmed exact decimals and all nine fractional timestamp digits.

Numeric typed NULL can change the comparison type of an `IN` predicate and remains conservatively handled. This patch does not push arbitrary expressions into MySQL.
