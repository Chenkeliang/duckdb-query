# DuckQuery v2.0.0 Release Notes

[中文](v2.0.0.md)

> DuckQuery major release: `2.0.0`  
> DuckDB Python package: `1.6.0.dev379`  
> DuckDB engine: `v2.0.0-alpha39998`  
> New-database storage: `v2.0.0`

## Major-version boundary

DuckQuery 2.0 adopts both the DuckDB 2.0 engine and v2 storage. Newly created `main.db` and
`system.db` files use the `v2.0.0` storage format and are no longer written for DuckDB 1.5
compatibility. DuckDB 2.0 can open older databases, but DuckQuery never silently rewrites them
at startup; an offline, explicit migration is required to gain v2 storage capabilities.

After migration, DuckDB 1.5.3 cannot directly open the v2 file. Back up before upgrading.
Downgrading requires restoring that backup or exporting with DuckDB 2.0 and importing with the
older engine.

## Highlights

- Added user database connection, DuckDB memory and spill budgets, low-disk admission checks, and settings for backup inspection and recovery guidance.
- Snapshot main/system and their WAL files, then write and fsync durable recovery markers before the first replacement. Process interruption or any database failure rolls back the complete set; startup is blocked if recovery fails.
- Fixed SQL literal token misclassification and stale extension retry status.
- Simplified storage settings, aligned actions, and fixed long-field overflow in agent messages.
- Fixed Issue #37: external DuckDB tables preserve their catalog in zero/multiple-column pivot modes, with qualified SQL available to synchronous and asynchronous execution.
- Added a versioned DuckDB capability contract that separates engine, direct SQL, Agent, and MCP support. MCP is now 0.4.0 and prefers the backend's shared safety classifier.
- Agent prompts are derived from the contract: VARIANT, JSON mutation, and lambda-colon syntax are available; `APPROX NEAREST`, `USING KEY`, and `FETCH` remain direct-SQL/MCP-only until table-scope auditing can parse them reliably.
- MCP 0.4.0 is published on PyPI, and its wheel also ships with this release.
- Fixed DuckDB 2.0 MySQL native pushdown silently converting `SUM(DECIMAL)` to DOUBLE. This engine/extension build now uses the verified safe path, and the capability contract reports exact extension builds and the block reason.
- Federated inline save now materializes once into staging, previews that same result, and publishes transactionally. Cancellation is linearized with commit, and retries retire old remote-session cancellation callbacks.
- MySQL/PostgreSQL query attachments are `READ_ONLY`; PostgreSQL connections inherit a server-side `statement_timeout`. Empty PostgreSQL passwords no longer swallow the port, and empty MySQL passwords omit the unsupported empty option.
- JSON/VARIANT viewing and copying preserve large integers, exact decimals, exponent notation, and duplicate keys. The editor vocabulary now includes `json_remove`.

- Uploads and URL imports stage data in bounded streams; URL metadata and downloads validate each redirect, with validated IPs pinned for direct connections.
- Excel parsing checks archive expansion budgets; storage migrations compare object definitions and row counts before replacement.
- Docker binds to loopback by default; release builds require reusable test and code-quality workflows to pass.

- Handwritten SQL supports `APPROX NEAREST`, recursive CTE `USING KEY`, `FETCH FIRST/NEXT`, VARIANT, and JSON mutation.
- Total-row LIMIT semantics cover sync, federated, async, save, export, and MCP paths, including 2.0 syntax not yet parsed by sqlglot.
- Dynamic Pivot now uses a DuckDB 2-compatible outer statement.
- Structured Parser/Binder locations are rendered directly in CodeMirror.
- About reports the app, Python package, engine, target storage, and actual database storage versions separately.
- The browser demo reports its independent Wasm engine instead of inheriting backend capabilities.

## Official compatibility changes

- **Storage**: v2.0.0 is the new format. New engines read old files, while old-engine access to new files is best effort; DuckQuery treats it as unsupported.
- **Lambda syntax**: legacy `x -> x + 1` is disabled by default; use `lambda x: x + 1`. `->` remains the JSON operator.
- **Extensions**: binaries remain tied to a DuckDB version and platform and must be replaced with matching v2 artifacts.
- **SQL parser**: v2 uses the new PEG parser. Error locations and message text may change, so callers must not parse fixed English messages.
- **ICU**: time zones, calendars, and locale collations are provided by the `icu` extension; it must be available when those features are used.
- **Preview status**: DuckDB explicitly marks alpha clients as not production-ready. The complete matrix must be rerun on the latest 2.0 build before publication.

## Extensions and packaging

- Extension metadata separates UI name, `LOAD` alias, canonical artifact, source, and runtime status.
- `mysql` and `postgres` map to `mysql_scanner` and `postgres_scanner`.
- Candidates have a decompressed-size limit and are verified by exact path with autoinstall disabled; failures cannot overwrite a working artifact.
- Windows uses a rollback slot for loaded-DLL file locking.
- Desktop and Docker resolve v2 extension paths from actual `version()` and `PRAGMA platform` values.

## Upgrade procedure

1. Stop DuckQuery and back up `main.db`, `system.db`, and their `.wal` files.
2. Install DuckQuery 2.0. The first launch shows a major-version notice and the actual storage versions of existing databases.
3. Older databases can be used in place. “Not now” dismisses the modal for the current launch; it can be reopened from Settings → DuckDB database storage, and returns next launch. No persistent top banner remains.
4. “Back up and upgrade” plus both confirmations only schedules migration. Desktop restarts and migrates before creating pools. Alternatively, stop the service and run from `api/`:

   ```bash
   python scripts/migrate_storage_to_latest.py --dry-run --target-storage v2.0.0
   python scripts/migrate_storage_to_latest.py --target-storage v2.0.0
   ```

5. Validate tables, constraints, indexes, views, sequences, macros, and critical queries before deleting the pre-upgrade backup.
6. Standard packages may download v2 extensions on first use; use an `-offline` package in air-gapped environments.

## Not exposed yet

- `CONNECT` / Quack, triggers, and DML-in-CTE;
- arbitrary `INSTALL` / `LOAD` SQL and custom extension repositories;
- a native stable-C-API module.

These require dedicated permission, audit, pooled-session lifecycle, and rollback designs—not merely parser support.
