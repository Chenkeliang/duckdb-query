# DuckQuery v2.0.0 发布说明

[English](v2.0.0_en.md)

> DuckQuery 大版本：`2.0.0`  
> DuckDB Python：`1.6.0.dev379`  
> DuckDB engine：`v2.0.0-alpha39998`  
> 新建数据库 storage：`v2.0.0`

## 大版本说明

DuckQuery 2.0 全面采用 DuckDB 2.0 engine 与 v2 storage。新建的 `main.db`、`system.db`
使用 `v2.0.0` 存储格式，不再为 DuckDB 1.5 保留输出兼容。DuckDB 2.0 可以直接读取旧版
数据库，但旧文件不会在启动时被静默重写；要获得 v2 storage 能力，必须在停止服务后显式迁移。

迁移到 v2 storage 后，DuckDB 1.5.3 不能直接打开该文件。升级前必须备份；降级只能恢复备份，
或用 DuckDB 2.0 将数据导出后再交给旧版导入。

## 主要更新

- 增加用户库连接、DuckDB 内存与溢写预算，低磁盘时拒绝新连接；设置页提供预算说明与备份检查、恢复指引。
- 迁移前成套备份 main/system 与 WAL，并在第一次替换前写入、fsync 持久化恢复标记；进程中断或任一数据库失败时整套回滚，恢复失败则阻止启动。
- 修复 SQL 字面量中的分号、LIMIT/FETCH 和括号误判；扩展重试不再复用旧终态缓存。
- 精简存储设置文案并统一按钮对齐，修复智能体长字段名溢出。
- 修复 Issue #37：外部 DuckDB 连接表在零列/多列透视模式下保留 catalog，完整限定 SQL 可同步、异步执行。
- 新增版本化 DuckDB 能力契约，明确区分引擎、手写 SQL、Agent 与 MCP 支持状态；MCP 升级至 0.4.0，并优先使用后端统一安全分类。
- Agent 提示词从能力契约生成：VARIANT、JSON mutation、新 Lambda 写法可用；`APPROX NEAREST`、`USING KEY`、`FETCH` 在表范围审计支持前仅开放给手写 SQL 与 MCP。
- MCP 0.4.0 已发布到 PyPI，wheel 同时随本 Release 提供。
- 修复 DuckDB 2.0 MySQL 原生远端下推将 `SUM(DECIMAL)` 静默降为 DOUBLE 的精度问题：当前引擎/扩展组合默认走已验证安全路径，能力契约公开实际扩展版本与阻止原因。
- 联邦内联保存改为单次 staging 物化、预览同源、事务发布；取消与提交具有明确先后关系，重试不会保留旧远端会话的取消器。
- MySQL/PostgreSQL 查询挂载增加 `READ_ONLY`；PostgreSQL 新连接继承服务端 `statement_timeout`，并修复空密码导致端口配置失效。MySQL 空密码改为省略密码参数。
- JSON/VARIANT 查看与复制保留超 JavaScript 精度的大整数、小数、指数和重复键；编辑器补齐 `json_remove`。

- 普通上传和 URL 导入改为流式暂存与实际字节限制；URL 元信息/下载逐跳校验地址，直连固定已验证 IP。
- Excel 解析前检查展开体积；存储迁移在替换前核验对象定义和行数。
- Docker 默认仅监听本机；正式构建必须先通过可复用测试与代码质量工作流。

- 手写 SQL 支持 `APPROX NEAREST`、递归 CTE `USING KEY`、`FETCH FIRST/NEXT`、VARIANT 与 JSON mutation。
- 总 LIMIT 覆盖同步、联邦、异步、保存、导出和 MCP，包括 sqlglot 暂未识别的 DuckDB 2.0 语法。
- 修复 DuckDB 2.0 动态 Pivot 的 CTE 绑定错误。
- Parser/Binder 的结构化位置直接标记到 CodeMirror 编辑器。
- About 页分别显示应用、Python 包、engine、目标 storage 和现有数据库实际 storage。
- 浏览器 Demo 显示独立 Wasm engine，不冒充桌面版 / Docker 的 2.0 能力。

## 官方兼容性变化

- **存储格式**：v2.0.0 是新的默认格式；新引擎向后读取旧文件，但旧引擎读取新文件仅属 best effort，本项目按“不兼容”处理。
- **Lambda 语法**：旧 `x -> x + 1` 默认禁用，应改为 `lambda x: x + 1`；`->` 继续作为 JSON 运算符。
- **扩展二进制**：仍与 DuckDB 版本和平台绑定，升级后必须使用 v2 对应 artifact。
- **SQL Parser**：2.0 使用新的 PEG parser，错误位置和部分错误文本会变化；调用方不得解析固定英文消息。
- **ICU**：时区、calendar 与地区 collation 由 `icu` 扩展提供；使用 IANA 时区名或地区排序时必须保证扩展可用。
- **Preview 风险**：官方明确 alpha client 尚未 production-ready；正式发布前必须再次基于最新 2.0 build 跑完整矩阵。

## 扩展与打包

- 扩展目录分离 UI 名、`LOAD` 名、canonical artifact、来源和安装状态。
- `mysql` / `postgres` 正确映射为 `mysql_scanner` / `postgres_scanner`。
- 候选文件受解压大小限制，并在 autoinstall=false 下按精确路径验证；失败不会覆盖可用文件。
- Windows 使用 rollback slot 处理已加载 DLL 的文件锁。
- Docker 与桌面版按实际 `version()` / `PRAGMA platform` 下载并播种 v2 扩展。

## 升级步骤

1. 停止 DuckQuery，并备份 `main.db`、`system.db` 及对应 `.wal`。
2. 安装 DuckQuery 2.0；首次启动会显示大版本提示和现有数据库实际 storage 状态。
3. 旧库可以先原样使用。选择“暂不升级”后，当前启动不再弹窗；可从“设置 → DuckDB 数据库存储”再次进入，下次启动也会重新提示。页面不常驻顶部横幅。
4. 页面选择“备份并升级”并完成双重确认后，只会登记待迁移任务；桌面版重启后在连接池建立前执行。也可以停止服务后在 `api/` 手工运行：

   ```bash
   python scripts/migrate_storage_to_latest.py --dry-run --target-storage v2.0.0
   python scripts/migrate_storage_to_latest.py --target-storage v2.0.0
   ```

5. 验证表、约束、索引、视图、序列、宏以及关键查询后，再决定是否清理升级前备份。
6. 标准包可能在首次使用时下载 v2 扩展；无外网环境使用 `-offline` 包。

## 暂不开放

- `CONNECT` / Quack、Triggers、DML-in-CTE；
- 任意 `INSTALL` / `LOAD` SQL 与自定义扩展仓库；
- 原生稳定 C API 模块。

这些能力不是语法识别问题，而是需要权限、审计、连接池生命周期和回滚模型后才能安全开放。
