# DuckQuery v2.1.0 Release Notes

This update refreshes the everyday query workflow, from connecting data and writing SQL to waiting for results and working with the agent.

## Highlights

- **A clearer workbench.** Reorganized navigation, data sources, settings, and results, with consistent light / dark themes and Chinese / English UI, a command palette, and common shortcut actions.
- **Long queries keep running.** Move an active read-only query to the background without executing it again, then restore the result from the task panel. Fixes failure/cancellation races and leftover request signals. Result columns show resolved table and field origins, including name-aligned unions.
- **More relevant SQL completion.** Table, column, and function suggestions follow statement context and typed prefixes. Manual completion and quoted table names remain available.
- **Easier agent input.** Multiline input, IME protection, and `@` table selection. Explain / Optimize actions fill a draft first. Sources and table scope share one compact row, with an add-source plus button and tooltip. Also fixes docking when returning from a narrow window to desktop.
- **Review AI edits before applying.** Returned SQL opens in a diff preview; changes to the editor trigger a conflict warning. Applying updates the editor and does not execute SQL.

## Upgrade Notes

Upgrading from v2.0.x introduces no new storage migration. DuckDB remains `v2.0.0-alpha39998`, Python package `1.6.0.dev379`, and new-database storage `v2.0.0`; this update does not switch to a stable engine. MCP remains `0.4.0`.

Before upgrading from 1.x, back up databases and WAL files and read the [2.0 major-version notes](https://github.com/Chenkeliang/duckdb-query/blob/v2.0.0/docs/releases/v2.0.0_en.md). macOS Apple silicon, macOS Intel, and Windows x64 retain standard and offline installers.

## Validation Scope

Local checks covered frontend, backend, MCP, and Rust tests, plus SQL-completion, AI-panel, column-origin, and cancellation regressions. Type checking, lint, builds, and direct macOS UI verification passed. Release CI separately checks real MySQL/PostgreSQL semantics and builds for all three desktop platforms. Windows and Intel Mac were not tested on local hardware.
