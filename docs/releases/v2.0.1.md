# DuckQuery v2.0.1 发布说明

本次补丁聚焦联邦查询的正确性、性能和桌面使用体验。MySQL 查询、保存、异步执行、导出和 AI 查询共用执行逻辑，减少各入口行为不一致的问题。

## 主要更新

- **MySQL 查询提速且保留精确结果**：对可安全识别的字符串等值和 `IN` 条件先在远端筛选候选，再由 DuckDB 完成精确过滤、JOIN、排序和 LIMIT，避免 MySQL 排序规则导致大小写、尾随空格或关联行数变化。无法安全优化时保留本地计算。
- **修复桌面 SQL 边界问题**：`IN (..., NULL::VARCHAR)` 不再因此放弃候选筛选；独立 `mysql_query('连接别名', ...)` 可自动附加已保存连接。同一连接通过多个 SQL 别名使用时均保留绑定，dollar-quoted SQL 内容不会被误判为本地表引用。
- **保护数据精度**：金额、大整数、纳秒时间戳及 JSON/VARIANT 数字文本在查询、查看、复制、保存和导出中保真；修复部分 MySQL 文本返回 BLOB、JSON 查看器翻译位置错误等问题。
- **保存与取消更可靠**：统一临时结果的事务和清理边界，保存只物化一次；取消不会因注册时序丢失，失败和超时不覆盖原有结果表，本地保存不再误用联邦查询超时。
- **PostgreSQL 远端执行可控**：连接按剩余预算设置服务端截止时间，取消绑定到本次任务；MySQL/PostgreSQL 查询挂载使用只读模式。
- **SQL 错误更易定位**：结构化 Parser/Binder 错误定位到原 SQL，迟到的错误不会标记到已修改的编辑器内容；能力信息反映当前引擎、扩展和实际启用的优化策略。

## 升级说明

- 从 **v2.0.0** 升级无需新的存储迁移；应用版本升至 **2.0.1**，DuckDB Python 仍为 `1.6.0.dev379`，engine 仍为 `v2.0.0-alpha39998`，新建数据库存储格式仍为 `v2.0.0`。
- 底层 DuckDB 仍为 Preview。若从 1.x 升级，请先阅读 [2.0 大版本升级说明](https://github.com/Chenkeliang/duckdb-query/blob/v2.0.0/docs/releases/v2.0.0.md) 并备份数据库。
- 支持 macOS Apple Silicon、macOS Intel 和 Windows x64；标准包支持应用内更新，`offline` 包面向无法在线下载扩展的环境。
- MCP 保持 `0.4.0`，本次无需单独升级 MCP 包。

## 验证

- 后端全量 **1534 passed，5 skipped**（含隔离 MySQL 8.4 回归）；MySQL 5.6 补充回归 **167 passed**。
- 前端全量 **1280 passed，1 skipped**；ESLint、TypeScript、生产构建及后端 pylint **10.00/10** 通过。
- 在重新打包的 macOS 桌面页面直接验证 typed NULL、独立 `mysql_query`、同连接多别名、保存、异步执行和 Parquet 导出；读回导出文件确认金额与 9 位小数秒完整保留。

数值类型的 NULL 可能改变 `IN` 的比较类型，因此仍保守处理；本次没有把任意表达式下推至 MySQL。
