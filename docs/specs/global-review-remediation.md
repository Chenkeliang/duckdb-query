# 全局审查修复记录（2026-09-07）

本批优先修复已确认的读取边界、发布门禁和迁移核验，保留既有本地工具定位。

## 读取入口

- 普通上传使用唯一且清洗后的文件名，按 1 MiB 分块读取；超限返回 413，并清理部分文件。文件只暂存一次。
- Excel ZIP 解析前检查声明展开体积（默认 512 MiB，`DUCKQUERY_MAX_EXCEL_EXPANDED_BYTES` 可调整）和成员数（最多 10,000）；该检查不等同于解析器进程内存硬限额。
- URL 元信息和导入共用 HTTP(S) 地址策略，允许正常内网源，拒绝 loopback、link-local、保留地址及 URL 内凭据。
- 每次重定向重新校验；直连将套接字目标固定到已检查的 IP，HTTPS 保留原主机 SNI/证书校验；不通过全局 DNS monkeypatch 影响其他请求。
- 环境代理仍兼容。代理是显式信任的网络边界，代理侧 DNS 和出口访问策略须由部署者配置；本地无法保证代理解析结果与本地相同。
- URL 文件先流式下载、限制实际解码后字节，再申请数据库连接。`prefer_native` 为兼容保留，不再让 httpfs 绕过网络校验。远程 Parquet 会完整暂存，牺牲远程范围读取性能换取统一资源限制。

## 发布与部署

- Compose 前后端默认仅绑定本机；移除 nginx 任意 Origin 放行。
- Tests 和 Code Quality 作为 reusable workflow，Release 必须等待二者通过。前端生产 build 纳入 Tests。
- Alpha 阶段 GitHub Release 标记 pre-release；正式 GA 需另行更改该发布策略。
- 本批不添加多用户账户系统。共享部署须使用带认证的反向代理，禁止直接开放未鉴权端口。

## 迁移核验与恢复

- 原生 COPY 完成后、替换前，比较各 schema 的表、列类型/默认值、索引、约束、视图、序列属性、宏及精确行数。不匹配拒绝替换。
- 此核验不等同于所有行值的逐字节比对。两个文件不是文件系统级单次原子替换，但迁移前会持久化完整集合恢复标记；进程中断或任一文件失败后按同一备份整套回滚，无法恢复时阻止启动。
- 恢复必须停止应用并确认没有后台连接；保留当前库副本，再将同一次迁移备份里的 main.db、system.db 及存在的 WAL 成套恢复到原位置。若备份没有 WAL，不得混用当前库 WAL。用迁移前版本启动并核对表与关键查询。
- 本批测试只使用临时数据库；没有对用户当前数据库执行迁移或恢复。

## 资源与恢复入口

### 本轮追加：资源与恢复入口

统一资源预算在连接正常/回退配置完成后应用：取配置内存与物理/cgroup v1/v2 上限的 75% 较小者。用户库池最多 `min(pool_max_connections, max_concurrent_queries)` 个连接（默认 4）；DuckDB 临时溢写上限 `duckdb_max_temp_directory_size` 默认 4GB，取得连接前对数据库与溢写文件系统检查 `min_free_disk_bytes`（默认 256MiB）。这些设置在 app-config.json 中修改，重启生效。

此预算不限制整个进程 RSS，也不为已执行查询预留磁盘；其他进程仍可消耗磁盘。文件导入、导出文件和迁移备份不属于 DuckDB 溢写配额。低磁盘时需先通过系统文件管理器清理可丢弃的临时文件或扩大磁盘，不要删除正在使用的数据库/WAL。

恢复 UI 提供按需备份检查、重新检查、桌面打开目录和四步恢复指引。备份检查验证成套文件存在并可只读打开，不宣称逐行内容验证；后端再次核验路径与桌面标志后才打开目录，无任意路径参数。未增加自动恢复操作。预算与备份 GET 不依赖用户连接池，数据库状态不可用时仍可进入恢复指引。
